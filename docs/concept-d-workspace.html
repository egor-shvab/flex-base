Concept D of 3 · plain & familiar

Workspace

The design idea is that there is no design idea: this looks like the office tools people already use every day, so nothing has to be learned. Every action is a word, not a symbol. One search box. One blue. One card holding the data. Nothing on screen that does not do a job.

This is a living reference, not a specification. It tracks the implementation rather than the other way round: where the two disagree, the code is right and this document is updated to match. Metrics below are the project's real tokens. Last synced 3 August 2026.

  • Base 16px
  • Row 44px
  • Controls 36px
  • Radius 8px
  • Contrast body 16:1 · links 5.4:1
  • Icons always beside a word

Why this is easy to learn

  • Words beat symbols Filter, Sort, Choose columns, Add a deal — no icon has to be decoded, and every icon has a label beside it.
  • One search box, top left Where every product this audience uses already puts it. A second, clearly narrower box searches only the open table.
  • One primary action Exactly one blue button per screen, first in reading order. If you don't know what to do, do the blue thing.
  • Filters read as a sentence "Showing 412 of 1,284 deals that match: Value is 8,000 or more" — no operators, no drawer, and removing a filter is an X on the part you don't want.
  • Nothing is hidden until hover The row menu is always visible, so there is nothing to discover by accident.
  • Empty means empty, not blank Every empty state names the thing that is missing and gives one button that fixes it.
  • Yes/No, not a tick A checkmark next to nothing is ambiguous; the words never are.
  • "Not set" instead of a dash A dash makes people wonder if something broke.
  • 44px rows, 16px base text Comfortable for eight hours and for eyes that aren't 25 any more. Sizing is in rem, so it grows with the browser's own text setting.

Token spec

Token Value Rationale
Neutrals #FFFFFF surface #F7F8FA page · row hover #EEF0F3 control hover #E8EAEE row rule #DCDFE4 border #5B6370 secondary #1F2126 text Two greys of text — body 16:1, secondary 6.0:1, both well past AA. Two of rule: the lighter one separates rows inside a box, the darker one is the box. And two of hover, which is the subtler distinction: a hovered control takes the darker wash, a hovered row the lighter one, because a badge has no border of its own and the darker wash is the same value as its fill.
Accent #1C64D8 #E7EEFC One blue, three jobs: the primary button, links, and the current page in the sidebar. 5.4:1 on white, so it works as text and not only as a fill.
Badge colours gray red orange yellow green teal blue indigo purple pink A closed ramp of ten hues, three steps each — fill, text, edge. The colour is a property of an individual SELECT choice, stored as a name and picked by whoever built the table, so there is no built-in "stage" vocabulary to learn. Storing a name rather than a value means a re-theme moves every badge, and no one can pick a pairing that fails contrast: every text step clears 4.5:1 on its own fill. The edge step is spent only on the colour picker's swatches, which have no word beside them; a badge is bounded by the value it wraps.
Type System stack · xs 12 / sm 14 / md 16 / lg 18 / xl 24 · weights 400 / 500 / 600 / 700 · line-height 1.5, tight 1.25 16px base, not 13. This audience includes people who enlarge text in their browser, and rem-based sizing means the whole UI grows with them. Five steps and no half-pixels — a ramp only stays a ramp if nothing lands between its rungs.
Space 8-base: 8 / 10 / 14 / 16 / 20 / 24 / 32 · row 44 · cell 16 · gutter 32 The row is the control height plus its 8px inset, so a row is exactly a button and follows it if the control height ever moves.
Targets 36 × 36 house floor — every sized control, icon-only buttons included The AA requirement is 24 × 24 (SC 2.5.8); 44 × 44 is SC 2.5.5, which is AAA. 36 sits deliberately between the two: comfortable with a trackpad, a mouse or an unsteady hand, without spending the vertical room a data table needs. Nothing goes below 24 — the filter chip's remove button sits exactly on it.
Radius 8 on buttons, inputs and the card · 4 on small markers · pill on chips and badges · 50% on avatars Soft enough to feel friendly, square enough to feel like a tool.
Elevation 0 1px 2px rgb(31 33 38 / 6%) on the card · 0 6px 20px rgb(31 33 38 / 12%) on menus Only two, and the second exists purely to say "this floats and will close".
Focus outline: 1px solid #3478E5 flush on a button or link, border-color: #3478E5 on a field, and box-shadow: 0 0 0 4px #E7EEFC on both The search field's own focus, generalised: a blue edge with a pale halo outside it, one step lighter than the accent so it reads as a signal rather than a second border and stays visible on a filled accent button. A field already draws an edge, so it recolours that one rather than gaining a second a hairline outside it. Never removed — the single most-skipped accessibility basic; the halo is what makes it feel soft.
Icons 20px, 1.7px stroke, one family, never used alone except the row menu An icon here is a speed aid for people who already know the word beside it.
