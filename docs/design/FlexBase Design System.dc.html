FlexBase Design system v1

A design system and product concept for a metadata‑driven table platform

Every screen here is generated from field definitions rather than drawn per entity. The system therefore has to be legible at any shape a user gives it: 4 fields or 40, one table or eighty, a single owner or a workspace with custom roles. Light, neutral surfaces carry the chrome; colour is reserved for data — field types, choices, statuses, roles — so orientation comes from hue, not from decoration.

01 — Foundations

Neutral chrome, coloured data

Two colour systems that never mix. Interaction colour is a single deep green used for focus, primary actions and selected state. Categorical colour is a closed set of ten hues a user assigns to their own values — retuning the accent can therefore never re-tint someone's data.

02 — Components

A small kit, used everywhere

Because forms, filters and cells are all generated from field metadata, every control has to survive being placed in any of the three. So the kit stays small and each part declares its own height, its own truncation and its own focus state rather than depending on where it lands.

Buttons — seven variants, five states each

The variant is a claim about consequence, not about emphasis: exactly one primary per surface, danger only for something irreversible, ghost for the toolbar, link inside a sentence. Every variant keeps the same 36px box and 8px radius, so swapping one for another never reflows a row.

Composition

A leading glyph is allowed, a trailing one only for a split button. Full width belongs to bottom sheets and narrow forms, never to a desktop toolbar.

Rules

Two focus registers: the border recolours on any focus, the 4px halo only on keyboard focus. Loading keeps the label and its width — a button that becomes a spinner moves the row under the cursor. Disabled is never the only explanation; the reason sits beside it in 12px. A ghost button's padding is transparent, so space it from the ink of its neighbour, not from its box. One size: every control that edits or commits a value is 36px tall, on desktop and on mobile alike. Compact chrome — filter chips, pagination cells, a toast’s Undo — sits between 24 and 30px, and a text link may be smaller still, so it can sit inside a line of copy.

Select — nine trigger states, one panel

One control covers SELECT fields, relations, user pickers and every filter, so its content is whatever the field metadata says. Search lives in the trigger, not in the panel: focus turns the trigger into a search box, and the panel below stays a plain list of options in every mode. Selection is shown by a tint and a check — never a checkbox, never a border. The trigger shows one value at most; everything else is counted.

Only the main text truncates. The id, the role, the +N counter, the clear and the caret are never shortened and never pushed out — they keep their width and the name gives way to them. The same rule holds inside the panel, so a name that is cut in the trigger is cut at the same point in the list.

Rules

The trigger shows one value and a count, never a bare “3 selected”. Clear sits next to the caret whenever anything is selected, and is the only affordance that removes everything at once. Colour comes from the choice, so the closed select has no accent of its own — the ring on focus is the only one.

Options keep their own order; a selected value is never floated to the top, because the list is also how a user learns what exists. A value whose choice was deleted stays visible until the user changes it rather than disappearing.

Text input — four variants, five states each

One box for every typed value: TEXT, NUMBER, dates and search alike — a number gets no glyph and no formatting of its own, so the four variants differ only in what sits inside the box. One focus state, the same whether it came from a click or a Tab: recoloured border plus a 4px halo. An error recolours the border and adds a line of 12px below; it never changes the height of the box, so a row of fields does not reflow when one of them fails.

Anatomy

Label above, always; the placeholder is not a label and disappears as soon as typing starts. A hint and an error occupy the same line — the error replaces the hint rather than stacking under it.

Rules

Validation happens on blur, not on keystroke, so a half-typed number is never called wrong. Once a field is in error it revalidates as you type, so the message can leave the moment it stops being true. Disabled carries its reason beside it in 12px; a read-only value drops its border entirely, because it is text and not a target. Every typed value is 14px regular and left-aligned, numbers included — a field is not typeset differently because of what it holds. Only machine-formatted values, dates and times among them, keep the mono face. The clear appears only while there is something to clear, and removes the value without opening anything.

Rules

Six options or a label that wraps means this is a select, not a segmented control. Exactly one segment is selected at all times, and the selection applies on click — there is no empty state and no Apply. Labels are one word where possible and never uppercased, so a value from a SELECT field can be a segment. The whole control is one tab stop; arrows move between segments and change the value as they go. A glyph never replaces the word except in the toolbar's icon-only form, where the tooltip carries it. Disabling single segments is not allowed: either the whole control is disabled, or the option is not offered.

Overlays — four containers, one rule each

Everything that covers the screen is one of these four, or a popover — and which one it is is decided by the work inside, not by how much room the content happens to need. All four share the same scrim, the same 52px header, the same 16px body padding and the same footer with the primary action on the right; they differ in where they attach and in whether the screen behind stays usable. Anchored lists — select panels, the colour picker, row menus — are popovers, and follow the select's panel rules instead.

Which one

Does the user need the screen behind? Side panel. Must the work finish before anything else? Modal. Is it a question with no fields? Dialog. Is the viewport narrow? Whatever it was, it is a drawer.

A footer means the work is saved as a whole; no footer means each field saves itself. A container never has both. Destructive actions sit at the left end of the footer, far from the primary, and open a dialog of their own.

Behaviour, all four

Focus moves into the container on open and returns to the element that opened it on close. Tab is trapped in a modal, a dialog and a drawer; it is not trapped in a side panel, which is part of the page. Esc closes, except with unsaved edits, where it asks. The scrim is 40% #18181b with no blur — blurring the data behind makes an overlay feel like a page change, and it is not one.

Nothing animates for longer than 160ms: modal and dialog fade with a 4px rise, panel and drawer slide from their own edge. An overlay never opens on load and never carries a breadcrumb.

03 — Field types

Eighteen types, four filter shapes

A field type is the atom of this product: it decides how a value is stored, how a cell reads, what control edits it and what shape its filter takes. Design‑wise the discipline is that a type may add a cell and an input, but it may not invent a filter shape — there are four, and adding a fifth is a system‑level decision, not a field one.

scalar

One value, one param. ?company=acme

list

Any of several — the param repeats. ?stage=Won&stage=Lost

range

Two inclusive bounds. ?value_from=1000&value_to=5000

boolean

Yes / No / All, where All is the absence of the param.

04 — The rules

Nine decisions this concept is built on

01Colour means data, never decorationTen categorical hues for values, statuses and roles; one green for interaction. Retuning the accent can never re‑tint someone's records.
02The URL is the stateView, filters, sort, page and the open record all live in the address, so every screen is shareable and Back always does one thing.
03No operators, anywhereA filter is one control per field and the value is the whole condition. It is what keeps a generated screen legible at 40 fields.
04Every state has a nameNo tables, no fields, no matches, no access, failed to load. A generated interface has more empty states than a designed one, so each gets copy of its own.
05Permissions remove, never grey outA field you may not see is absent from the table, the form, the filters, the export and the API. A greyed value still leaks that it exists.
06Mono marks machine‑made valuesRecord numbers, field keys, params, ids, timestamps and formulas. If a person did not type it, it is set in IBM Plex Mono.
0724×24 is the floor, 36 is the house heightEvery control that edits or commits a value — buttons, inputs, selects, menu items, icon buttons — stands 36px tall. Compact chrome (chips, pagination, a toast’s Undo) may go down to 24px, which is the floor on either axis, and inline text links are the one thing allowed below it, so they read inside a sentence.
08Keyboard operation and visible focusEverything is keyboard‑operable and visibly focused. Dialogs and drawers are truly hidden when closed, never focusable content parked off‑screen.
09Contrast and hidden surfaces are checked, not assumedText holds 4.5:1, control outlines and other non‑text UI 3:1 — which is why control borders are a separate colour from dividers.
